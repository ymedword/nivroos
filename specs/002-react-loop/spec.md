## User Scenarios & Testing *(mandatory)*

### User Story 1 - CLI 多轮对话完成工具任务 (Priority: P1)

用户在命令行与 Agent 对话，Agent 遇到需要外部数据的问题时自主调用可用工具
获取数据，基于结果继续推理并给出最终回答，全程无需用户指定调用哪个工具。

**Why this priority**: 这是 ReAct 循环的主链路——"想一步、做一步、看结果"的
完整闭环，也是 Demo 一的验收场景；其他场景都是它的退化或边界形态。

**Independent Test**: 以真实模型在 CLI 对话"查一下北京天气并告诉我穿什么"，
Agent 自主调用一次天气查询工具后给出穿衣建议（Demo 一人工验收）。

**Acceptance Scenarios**:

1. **Given** 用户在 CLI 发消息问天气，**When** 模型第一轮响应请求调用
   `http_get` 工具，**Then** 系统执行该工具并把结果回填对话历史，继续推理，
   最终返回基于天气数据的穿衣建议。
2. **Given** 一次响应包含多个工具调用，**When** 系统执行它们，**Then** 按
   顺序逐个执行，不并行。
3. **Given** 工具执行过程中任意环节失败，**When** 用户查看最终响应，
   **Then** 系统仍给出明确结果或错误说明，不静默中断。

---

### User Story 2 - 普通问答单轮直接返回 (Priority: P2)

用户问一个不需要工具的问题，Agent 单轮调用模型后直接返回答案。

**Why this priority**: 覆盖循环的"快速路径"——无工具调用时立即收敛，不做
多余轮次；是使用频率最高的日常形态。

**Independent Test**: CLI 中问"你好"，一轮模型调用后直接返回回答，无工具
调用、无多余迭代。

**Acceptance Scenarios**:

1. **Given** 用户问普通问题，**When** 模型响应不含工具调用，**Then** 系统
   直接返回该响应作为最终答案，循环结束。
2. **Given** 一轮调用完成，**When** 查看会话，**Then** 用户消息与模型响应
   都已累积进会话历史。

---

### User Story 3 - 会话与审计可追溯 (Priority: P3)

每次对话的完整过程（每轮模型调用、每次工具执行、成败状态）都有记录可查，
会话按固定规则唯一标识。

**Why this priority**: 可审计是 NivroOS 差异化能力（宪法原则五），但价值
依赖前两条链路先跑通。

**Independent Test**: 完成一次含工具调用的对话后，逐条核对审计记录：每次
LLM 调用与工具执行各有一条记录，成功失败状态与实际一致，且归属同一会话。

**Acceptance Scenarios**:

1. **Given** 一次对话产生 N 次 LLM 调用与 M 次工具执行，**When** 对话结束
   后核对审计记录，**Then** 恰好 N+M 条，每条含会话关联、成败状态与耗时。
2. **Given** 工具执行被白名单校验拒绝，**When** 核对审计记录，**Then**
   该次记录标记为失败并含拒绝原因。
3. **Given** 不同渠道/用户/Agent 组合，**When** 生成会话标识，**Then**
   标识唯一且由三者联合生成。

---

### Edge Cases

- 模型持续请求工具不收敛 → 达到最大迭代次数（默认 10）强制结束，返回固定
  提示文案"任务执行时间较长，达到最大轮数，已停止继续尝试，当前结果可能
  不完整。"并记录告警日志。
- 模型请求的工具不在可用列表 → 返回清晰错误，不中断会话。
- 白名单校验失败（域名不允许）→ 拒绝执行、审计记失败、结果回填继续推理。
- 模型调用失败（US-1 的 ProviderCallException 上抛）→ 异常经统一入口向上
  传播，不吞；上下文必须清理。
- 对话历史超过轮数上限（默认 20）→ 截断早期消息，保留近期对话。
- 引导文件缺失 → 告警但不阻断对话。
- 修改 Agent 指令文件 → 下一轮组装立即读到新内容（无缓存）。
- 处理过程中抛异常 → 当前 Agent 上下文必须清理，不得泄漏到后续请求。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须自实现 ReAct 循环：检查模型响应中的工具调用请求，
  执行后把结果回填对话历史并继续推理，直到无工具调用或达到迭代上限
  （宪法原则一，不得使用 Spring AI 的 Agent 抽象）。
- **FR-002**: 每次 LLM 调用与每次工具执行都必须写入审计记录，成功与失败
  都写，含会话关联（宪法原则五）。
- **FR-003**: 工具执行前必须做白名单校验（HTTP 域名白名单），校验失败
  拒绝执行并记录失败审计（success=false + 错误信息）。
- **FR-004**: 循环必须有最大迭代次数上限（默认 10，可在 Profile 覆盖），
  达到上限强制结束并给出明确提示，防止死循环。
- **FR-005**: 每轮 Prompt 组装必须包含：系统提示词（Agent 指令正文 + 引导
  文件 + 末尾当前日期时间）、对话历史（按轮数上限截断，默认 20 轮）、工具
  列表；长期记忆部分预留占位（US-3 接入）。
- **FR-006**: 统一入口必须管理当前 Profile 上下文（ThreadLocal），处理结束
  （含异常路径）必须清理，防止虚拟线程复用串号。
- **FR-007**: CLI 交互通道支持多轮对话，用户消息与每轮响应正确累积进会话。
- **FR-008**: 会话标识由渠道+用户+Profile 联合生成，且只在一处拼接。
- **FR-009**: 工具调用多个时按顺序执行，不并行（核心阶段）。
- **FR-010**: 文件加载（Agent 指令、引导文件）每次组装时重新读取，不缓存，
  修改后下一轮立即生效；引导文件缺失时告警不阻断。

### Key Entities

- **Session（会话）**：一次对话的上下文容器。属性：会话标识（渠道+用户+
  Profile 联合生成）、Agent 名、渠道、用户、对话消息列表、创建与活跃时间。
  核心阶段内存版，持久化留 US-5。
- **Profile 上下文**：当前处理的 Agent 配置的线程级持有（ThreadLocal），
  供循环与工具执行读取；处理结束必须清理。
- **Tool Invocation 审计记录**：每次工具执行的落库记录。属性：会话关联、
  工具名、入参、结果、成败状态、错误信息、耗时、时间。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 验收 Demo 一跑通：真实模型在 CLI 对话中自主调用天气查询工具
  并给出穿衣建议（本模块与 US-1 的联合验收锚点）。
- **SC-002**: 验收测试套件全部测试类全绿（harness 覆盖 FR-001~FR-010）。
- **SC-003**: 100% 的 LLM 调用与工具执行产生审计记录（含失败与白名单拒绝）。
- **SC-004**: 持续请求工具的循环在配置的迭代上限处精确强制结束，轮数
  不多不少。
- **SC-005**: 异常路径 100% 清理 Agent 上下文（由测试显式钉死，防止并发
  复用串号）。

## Assumptions

- 前序改造点（软门禁，实施时停下报告）：US-1 的审计写入接口增加会话标识
  参数；Agent 配置类增补工具列表与设置字段。
- 本模块无新增第三方依赖（HTTP 客户端用 JDK 自带）。
- 会话存储为内存版（US-5 落 SQLite）；工具池为简化形态（US-4 换完整注册
  体系）；白名单仅 HTTP 域名（US-4 补文件/Shell）。
- 迭代上限默认 10、历史轮数上限默认 20，均可按 Agent 配置覆盖。
- 模型行为（是否收敛、工具调用格式）由 US-1 的调用层保证。
